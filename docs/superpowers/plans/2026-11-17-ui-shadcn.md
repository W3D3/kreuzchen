# UI migration to shadcn-svelte Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every screen of the app to the shadcn-svelte look approved in the prototype (`src/proto/`, commits ad12d5f, ae269b3, 3b56ef4), keeping all behaviour.

**Architecture:** Tailwind v4 + shadcn-svelte (bits-ui) become the app-wide styling. The prototype's theme (app tokens mapped to shadcn variables, light/dark via `prefers-color-scheme` and `data-theme`) moves into `src/app.css`. Each screen is rewritten in place from its prototype counterpart, wired to the real data and logic. System `ask` dialogs become one in-app confirm dialog. The prototype and the `#proto` switch are deleted at the end.

**Tech Stack:** Svelte 5, Tailwind CSS 4, shadcn-svelte 1.8 (bits-ui 2.21), @lucide/svelte, Tauri 2.

**Spec:** the approved prototype screens (`src/proto/EditorProto.svelte`, `EntryProto.svelte`, `ResultProto.svelte`, `ThemeSwitch.svelte`, `proto.css`) are the visual spec. The current screens in `src/screens/` are the behaviour spec.

## Global Constraints

- Behaviour stays identical unless a task says otherwise. Every command call, argument, keyboard shortcut, validation and message keeps working.
- Entry keyboard flow is untouchable: `entryKey`, `entryItems` and the focus/keydown logic stay as they are. Digits/shortcut keys answer and advance; no animation may delay focus.
- German UI copy stays as it is today, except where a task names new copy.
- Light and dark must both work, by system preference and by the Einstellungen choice (`data-theme`).
- Public repo: no names of specific questionnaires or customers anywhere. Invented example data only.
- Commit with `git commit --no-gpg-sign`, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Verification per task: `npm test`, `npm run check` clean, and WebKit screenshots (light + dark) of the touched screens with stubbed Tauri IPC.

## Review Focus

1. Long content (long question texts, many answers, long file names, 65-item questionnaires) → wraps, no horizontal overflow at 1000px window width.
2. Keyboard-only use of the entry screen and of dialogs (Esc cancels, Enter confirms the focused button, focus returns afterwards).
3. A registry/locked definition (`locked: true`) in lists: the „Registry“ badge and disabled edit/delete stay.
4. Error banners (command failures) stay visible and readable in both themes.
5. Saved results opened from „Gespeicherte Auswertungen“ (outdated / missing definition notices, re-grade offer) render like fresh results.

### Task 1: App-wide foundation

**Files:** `src/app.css`, `src/main.ts`, `src/App.svelte`, new `src/lib/components/confirm.svelte.ts` + `src/lib/components/ConfirmDialog.svelte`, `src/lib/components/IconButton.svelte` (from `src/proto/IconBtn.svelte`); callers of `ask` in `src/App.svelte`, `src/screens/Entry.svelte`, `src/screens/Saved.svelte`, `src/screens/Definitions.svelte`.

**Produces:**
- Theme from `src/proto/proto.css` moved into `src/app.css` and loaded for the whole app. The old token names (`--bg`, `--fg`, …) stay defined, so not-yet-migrated screens still render.
- `confirm(opts: { title: string; message: string; confirmLabel: string; destructive?: boolean }): Promise<boolean>` rendering one app-level `ConfirmDialog` (mounted in `App.svelte`). It replaces every `ask(...)` from `@tauri-apps/plugin-dialog`, with the same wording as today's `ask` texts as `message`. Titles: use the `title` passed to `ask` today, or a short fitting one.
- App shell (nav, update bar, „Nach Updates suchen“ button, Einstellungen) restyled in the prototype's look.
- `src/screens/Settings.svelte` restyled with the shadcn radio-group.

**Tests:** `confirm` resolves `true` on confirm, `false` on cancel/Esc (unit test of the store logic in `confirm.svelte.ts`). Existing tests pass.
